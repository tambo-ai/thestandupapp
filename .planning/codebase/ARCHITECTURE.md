# Architecture

**Analysis Date:** 2026-03-03

## Pattern Overview

**Overall:** Hybrid client-server with AI-driven dynamic UI, organized as a full-stack Next.js 15 application integrating Tambo AI for generative components.

**Key Characteristics:**
- **Tambo AI Integration**: AI generates and controls React components dynamically; components are pre-registered with Zod schemas
- **Tool-Based Data Access**: External tools (Linear, GitHub) are exposed to AI via defined schemas; AI invokes them to gather data
- **Canvas-Based Layout**: Components render on a dismissable grid canvas (up to 4 visible simultaneously); AI can render multiple components in one response
- **Server-Resident Logic**: API routes handle Linear SDK and GitHub API calls; client sends token via headers; no secrets exposed to browser
- **Encrypted Token Storage**: User GitHub/Linear tokens stored locally in AES-GCM encrypted localStorage (key derived from userId via PBKDF2)
- **Session-Based Auth**: Better Auth manages Google OAuth; session stored in Turso SQLite database


## Layers

**Application Shell & Routing:**
- Purpose: Entry point, layout, page routing
- Location: `src/app/layout.tsx`, `src/app/page.tsx`, `src/app/login/page.tsx`, `src/middleware.ts`
- Contains: Next.js App Router pages, middleware for session checking, root layout with global styles
- Depends on: TamboProvider, authentication, Tambo tools/components
- Used by: Browser requests

**Tambo AI Orchestration Layer:**
- Purpose: Registers AI-accessible components and tools; defines system prompt with user context
- Location: `src/lib/tambo.ts`, `src/app/page.tsx` (AppShell)
- Contains: Component registry with Zod schemas, tool definitions (listTeams, getTeamMembers, findGitHubUser, searchIssues), system prompt builder
- Depends on: TamboProvider from `@tambo-ai/react`, component and tool definitions, user tokens
- Used by: TamboProvider to render available components and expose tools to AI

**UI Components (Tambo-Aware):**
- Purpose: Render dashboard components that can be generated by AI
- Location: `src/components/` (not in tambo/) and `src/components/tambo/`
- Contains:
  - Specialized components: `TeamOverview`, `PersonDetail`, `PullRequestList`, `WeeklyGoals`, `RiskReport`, `SummaryPanel`
  - Shared: `Graph`, `FilterPills`, `SettingsModal`, `UserHeader`
  - Thread UI: `MessageThreadFull`, `MessageInput`, `MessageSuggestions`, `ThreadHistory`, `CanvasSpace`
- Depends on: Tambo hooks (useTamboThreadInput), data fetching via useFetchJSON, Recharts for charts
- Used by: CanvasSpace to display rendered components, AI system

**Canvas Management:**
- Purpose: Display and manage lifecycle of rendered components in a grid layout
- Location: `src/components/tambo/canvas-space.tsx`
- Contains: Grid layout (1/2/3/4 components), dismiss/reorder handlers, MAX_VISIBLE = 4 limit
- Depends on: useTambo, useTamboThreadInput from SDK
- Used by: Root page layout, renders components from message stream

**Thread & Message UI:**
- Purpose: Chat interface, message display, input handling, suggestion pills
- Location: `src/components/tambo/message-*.tsx`, `src/components/tambo/thread-*.tsx`, `src/components/tambo/scrollable-message-container.tsx`
- Contains: Message rendering, input textarea, submit button, suggestion display, thread history sidebar
- Depends on: Tambo SDK hooks, thread management utilities
- Used by: MessageThreadFull, which assembles the left chat panel

**API Routes (Backend):**
- Purpose: Handle Linear and GitHub API calls with token-based auth; enforce token presence in headers
- Location: `src/app/api/linear/`, `src/app/api/github/`, `src/app/api/auth/`
- Contains:
  - Linear routes: `/team` (list/get members), `/search` (issue search), `/issues`, `/cycle`, `/risks` (risk detection)
  - GitHub routes: `/prs` (fetch PRs), `/find-user` (resolve email/name to GitHub username)
  - Auth: Better Auth OAuth handler
- Depends on: LinearClient SDK, GitHub REST API, next/server, withLinearClient/withGitHubToken wrappers
- Used by: Frontend API fetches, tools in tambo.ts via apiFetch

**Token Management:**
- Purpose: Store and encrypt user credentials locally (GitHub token, Linear API key, GitHub org, selected team, filtered members)
- Location: `src/lib/user-tokens.ts`
- Contains: AES-GCM encryption/decryption, PBKDF2 key derivation, localStorage scoped by userId
- Depends on: Web Crypto API, localStorage
- Used by: Client components, getTokenHeaders() helper

**Authentication:**
- Purpose: Session management, OAuth flow
- Location: `src/lib/auth.ts`, `src/lib/auth-client.ts`, `src/app/api/auth/[...all]/route.ts`
- Contains: Better Auth instance configured with Turso database, Google provider, React client hook
- Depends on: Better Auth, Turso (LibSQL), Kysely ORM
- Used by: Middleware (session check), AppShell (useSession hook)

**Client Utilities:**
- Purpose: Shared logic for data fetching, filtering, UI utilities
- Location: `src/lib/member-filter.ts`, `src/lib/use-fetch-json.ts`, `src/lib/thread-hooks.ts`, `src/lib/utils.ts`
- Contains: TeamMember type, fetchTeamMembers, resolveFilteredMemberNames, useFilteredMemberIds, useFetchJSON, useMergeRefs, positioning helpers
- Depends on: React hooks, user-tokens, localStorage
- Used by: Components, tambo.ts

**API Client Wrappers:**
- Purpose: Encapsulate token extraction and error handling for API routes
- Location: `src/lib/linear-client.ts`, `src/lib/github-client.ts`
- Contains: withLinearClient/withGitHubToken higher-order functions, linearClientFromRequest, GitHub header helpers, resolveGitHubLogin
- Depends on: LinearClient SDK, next/server
- Used by: All API route handlers

## Data Flow

**User Query → AI → Component Render:**

1. User types query in message input (left panel, `MessageThreadFull`)
2. Input sent via `useTamboThreadInput().submit()` → TamboProvider
3. AI receives system prompt (with user context: name, email, selected team, filtered members)
4. AI can invoke tools:
   - `listTeams()` → GET `/api/linear/team` → returns `[{id, name, key}]`
   - `getTeamMembers(teamId)` → GET `/api/linear/team?id=X` → returns members with status/issues
   - `findGitHubUser(email, name)` → GET `/api/github/find-user` → searches GitHub for user
   - `searchIssues(query)` → GET `/api/linear/search` → full-text issue search
5. AI generates response and components (from registered component list in tambo.ts)
6. Components render via Tambo SDK's `renderedComponent` → CanvasSpace collects them
7. CanvasSpace displays up to 4 most recent components in responsive grid

**Token Flow (Secured):**

1. User enters GitHub/Linear tokens in settings modal → encrypted and stored in localStorage (key derived from userId)
2. Each API call includes tokens via `getTokenHeaders()` → reads from localStorage, decrypts, adds to headers
3. API routes extract token from header (`x-linear-api-key`, `x-github-token`)
4. API routes call external APIs using token
5. Response sent back to client; token never travels to browser

**Component Self-Fetching:**

- Some components (`TeamOverview`, `RiskReport`) accept team ID and fetch their own data
- Others (`WeeklyGoals`, `SummaryPanel`) receive data pre-built by AI from tool results

## Key Abstractions

**TamboComponent Registry:**
- Purpose: Define what components AI can render and what props they accept
- Location: `src/lib/tambo.ts` (components array)
- Pattern: Each component has name, description, component ref, propsSchema (Zod)
- Examples: `TeamOverview`, `PersonDetail`, `WeeklyGoals`, `RiskReport`, `Graph`, `SummaryPanel`

**TamboTool Registry:**
- Purpose: Define what data-fetching functions AI can invoke
- Location: `src/lib/tambo.ts` (tools array)
- Pattern: Each tool has name, description, async handler, inputSchema, outputSchema (Zod)
- Examples: `listTeams`, `getTeamMembers`, `findGitHubUser`, `searchIssues`

**API Route Wrapper Pattern:**
- Purpose: Standardize token extraction and error handling across Linear/GitHub endpoints
- Pattern: `withLinearClient(handler)`, `withGitHubToken(handler)` — pass handler function that receives token or client
- Examples: All routes in `src/app/api/linear/` and `src/app/api/github/`

**Member Filtering:**
- Purpose: Allow user to focus on subset of team
- Type: `TeamMember` interface (linearUserId, name, avatar, email, status, inProgressIssues, topIssue)
- Helpers: `fetchTeamMembers()`, `resolveFilteredMemberNames()`, `useFilteredMemberIds()`

**Encrypted Token Storage:**
- Purpose: Safely store sensitive tokens in localStorage without exposing them
- Pattern: PBKDF2 key derivation from userId + salt → AES-GCM encrypt/decrypt
- API: `setGithubToken()`, `getGithubToken()`, `setLinearApiKey()`, `getLinearApiKey()`, `getTokenHeaders()`

## Entry Points

**Root Page (Authentication Required):**
- Location: `src/app/page.tsx`
- Triggers: Browser request to `/` (protected by middleware)
- Responsibilities:
  - Verify user session (useSession hook)
  - Load user's stored tokens, selected team, member filter
  - Build system prompt with user context
  - Render TamboProvider wrapping ChatPanel + CanvasSpace
  - Handle chat width resizing via draggable divider

**Login Page:**
- Location: `src/app/login/page.tsx`
- Triggers: Browser request to `/login` or when not authenticated
- Responsibilities: Display Google OAuth button, marketing copy, mock dashboard preview

**Middleware:**
- Location: `src/middleware.ts`
- Triggers: All requests except /login, /api/auth/*, /_next/*, static files
- Responsibilities: Check for session cookie; redirect to /login if missing

**API Auth Endpoint:**
- Location: `src/app/api/auth/[...all]/route.ts`
- Triggers: OAuth callbacks, session endpoints
- Responsibilities: Better Auth route handler (delegated by middleware)

**Tool Invocation Endpoints:**
- Location: `src/app/api/linear/*`, `src/app/api/github/*`
- Triggered by: AI via apiFetch() in tambo.ts
- Pattern: AI calls tool → tool calls apiFetch("/api/linear/team") → API route extracts token from header → calls Linear/GitHub API → returns JSON

## Error Handling

**Strategy:** Try-catch at route handler level with JSON error responses; client-side graceful degradation.

**Patterns:**

1. **API Route Errors:**
   - Linear/GitHub auth failures → 401 with `{error: "..."}` message
   - Missing teamId/required params → 400 with `{error: "..."}` message
   - Unexpected errors in try-catch → 500 with `{error: message}` message
   - Example: `src/app/api/linear/team/route.ts` wraps with `withLinearClient` which catches errors

2. **Component-Level Errors:**
   - useFetchJSON hook catches errors and returns error state
   - Components render error UI: `<p style={{color: "#C45555"}}>Failed to load...</p>`
   - Example: `TeamOverview` checks `if (error)` and shows error message

3. **Token Errors:**
   - Missing token → route returns 401 before calling external API
   - Decryption failures → return empty string (corrupted token)
   - Example: `linearClientFromRequest` checks header presence first

4. **AI/Tool Errors:**
   - Tool handler throws → wraps in try-catch, returns error message to AI
   - AI responds with human-readable error: "Could not fetch teams"
   - Tool input validation via Zod schemas prevents bad requests

## Cross-Cutting Concerns

**Logging:**
- Approach: `console.error()` for important failures (GitHub route errors)
- No centralized logging infrastructure
- Examples: `src/lib/github-client.ts` logs GitHub request errors

**Validation:**
- Approach: Zod schemas at multiple levels:
  - Tool inputs/outputs: `inputSchema`, `outputSchema` in tambo.ts
  - Component props: `propsSchema` (e.g., `teamOverviewSchema` for TeamOverview)
  - API query params: manual checks in route handlers
- Strict TypeScript enabled (tsconfig strict: true)

**Authentication:**
- Approach: Session-based (Better Auth) for user identity
- Token-based headers (x-linear-api-key, x-github-token) for API calls
- Middleware enforces session presence before allowing access to protected routes
- Tokens stored encrypted in localStorage, scoped by userId

**Caching:**
- Approach: HTTP Cache-Control headers on API responses
  - Team list: `max-age=300` (5 min) — slow-changing
  - Member details: `max-age=120` (2 min) — moderate activity
  - PR list: `max-age=120` — moderate activity
  - Risk report: `max-age=120` — re-check frequently
- No client-side caching framework (relies on HTTP caching)

**State Management:**
- Approach: React hooks (useState) for component-level UI state
- Tambo SDK manages thread state (messages, currentThreadId)
- localStorage manages user preferences (tokens, selected team, filtered members)
- No Redux/Zustand/global store
