  <name>Task 1: Fix connection status refresh with polling/retry and CSS overflow</name>
  <files>src/app/app/app-shell.tsx, src/app/globals.css</files>
  <action>
In `src/app/app/app-shell.tsx`, replace the current `refreshConnectionStatus` and `handleModalClose` with a polling-based approach that retries until it detects a change or times out:

1. Replace `refreshConnectionStatus` with a new `pollConnectionStatus` function:
   - Accepts no arguments.
   - Uses a loop that runs up to 6 attempts (total ~10 seconds coverage).
   - Delays: 500ms, 1000ms, 2000ms, 2000ms, 2000ms, 2000ms (exponential start, then plateau).
   - On each attempt, fetches `/api/connections/status`, parses JSON.
   - Compares the result against the CURRENT `connStatus` state. If EITHER provider changed status (e.g., was "not_installed" and is now "connected"), call `setConnStatus(data)` and stop polling.
   - After all attempts exhausted without change, still call `setConnStatus(data)` with the last result (in case both providers connected and no change detection was possible, or to at least update to the freshest value).
   - Use a `useRef` to store an AbortController so polling can be cancelled if the component unmounts or modal reopens.

2. Update `handleModalClose`:
   - Call `setModalOpen(false)` then `pollConnectionStatus()`.
   - Do NOT await pollConnectionStatus -- fire and forget so the modal closes immediately.

3. Add cleanup: in a `useEffect` cleanup, abort any in-flight polling when the component unmounts.

4. IMPORTANT: The `pollConnectionStatus` function needs access to the latest `connStatus` value without re-creating itself on every state change. Use a `useRef` to track the "pre-poll" snapshot:
   - Before starting the poll loop, capture `connStatusRef.current` as the baseline.
   - Keep `connStatusRef` updated via a `useEffect(() => { connStatusRef.current = connStatus }, [connStatus])`.
   - This way `pollConnectionStatus` can be a stable `useCallback` (no `connStatus` dependency) while still comparing against the latest known state.

In `src/app/globals.css`, add a CSS override AFTER the existing `@import '@workos-inc/widgets/styles.css';` line. Add this rule in the `@layer base` block or after it:

```css
/* Fix: Radix UI Inset overflow clips WorkOS Pipes dropdown menus (UAT test 7) */

  overflow: visible !important;
}
```

This overrides the Radix Themes Inset component's `overflow: hidden` which clips the three-dot dropdown menu rendered inside WorkOS Pipes card list items.
