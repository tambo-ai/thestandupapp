**Part A: Middleware removal detection.**

Read the existing middleware.ts. Find the section where it validates the active_team_id cookie against memberships (the existing code that clears invalid cookies -- referenced in STATE.md decision [Phase 02-03]). In that section, BEFORE clearing the cookie, check if the team was a non-personal team (is_personal = 0). If so, look up the team name and set a short-lived cookie:

```typescript
// When active_team_id is invalid (user was removed from team)
// Set a notification cookie so AppShell can show a toast
response.cookies.set("removed_from_team", teamName, {
  httpOnly: false,  // Client-side readable
  sameSite: "lax",
  path: "/",
  maxAge: 60,  // 1 minute -- just needs to survive the redirect
});
```

IMPORTANT: Only set this cookie when the team was a non-personal team AND the membership is genuinely missing (not just when the cookie is stale for other reasons). The existing middleware already distinguishes these cases.

If the middleware doesn't currently have the team name available at the point where it clears the invalid cookie, add a quick DB lookup to get the team name before clearing.

**Part B: AppShell toast rendering.**

In app-shell.tsx, add an effect that runs on mount:
1. Read the `removed_from_team` cookie from `document.cookie`
2. If present, extract the team name value
3. Delete the cookie immediately: `document.cookie = "removed_from_team=; path=/; max-age=0";`
4. Show a toast notification

Toast implementation (no library needed -- single use case):
- State: `const [toast, setToast] = useState<string | null>(null);`
- Effect: on mount, check cookie, set toast to "You were removed from {teamName}"
- Render: if toast is not null, render a fixed-position notification:
```tsx
{toast && (
  <div className="fixed bottom-4 left-1/2 -translate-x-1/2 z-[60] bg-[#1A1A1A] text-white text-[13px] px-4 py-2.5 rounded-lg shadow-lg transition-opacity duration-300"
    style={{ opacity: toast ? 1 : 0 }}>
    {toast}
  </div>
)}
```
- Auto-dismiss after 5 seconds: `setTimeout(() => setToast(null), 5000)`

**Part C: 403 redirect handling.**

In AppShell, add a global fetch error handler pattern. When any API call in the app returns 403, the component making the call should redirect to `/app` (letting middleware handle the rest). This is already implicitly handled by individual fetch calls in the Members tab. No additional global handler needed -- just document this as the established pattern.

However, add a note in the team-settings-modal.tsx (as a code comment) that if any fetch returns 403, the modal should close and redirect: `window.location.href = '/app'`. Apply this to all fetch calls in the modal (members, invitations, update, delete, leave).

**Part D: Pass team name to page.tsx for AppShell.**

Check if page.tsx (the server component) already has access to read cookies. If so, the removed_from_team cookie can be read server-side and passed as a prop. However, since this is a client-only cookie (httpOnly: false), it's simpler to read it client-side in AppShell via document.cookie. No server-side changes needed.
