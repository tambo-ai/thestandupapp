User upsert: Use `db.insertInto('users').values({...}).onConflict(oc => oc.column('id').doUpdateSet({...}))`. Per user decision: user record stores WorkOS user ID as primary identifier. Use `eb.ref('excluded.email')` pattern for the conflict update set (per research code example). Set `updated_at` to `sql\`datetime('now')\`` on conflict.

Personal team check: Query using `getFullDb()` to join teams and memberships tables — find a team where `is_personal = 1` and user has a membership. Per research open question, use the `FullDatabase` typed instance for this cross-table query.

Personal team creation (if missing): Use `getFullDb().transaction().execute(async (trx) => {...})`:
- Generate `teamId = crypto.randomUUID()`
- Build user name: `[user.firstName, user.lastName].filter(Boolean).join(' ') || 'User'`
- Insert into teams: `{ id: teamId, name: \`\${userName}'s Workspace\`, slug: \`personal-\${user.id}\`, is_personal: 1 }`
- Insert into memberships: `{ id: crypto.randomUUID(), team_id: teamId, user_id: user.id, role: 'owner' }`
- Per user decision: personal team named "{Name}'s Workspace" (e.g., "Avi's Workspace")

After upsert + team creation, set the `active_team_id` cookie to the personal team ID if no cookie is currently set. Note: `handleAuth` onSuccess runs inside a Route Handler context, so cookies can be set here. Use `cookies()` from 'next/headers' to check and set. Cookie config: HttpOnly, SameSite=Lax, path=/, Secure only if NODE_ENV=production, maxAge=30 days.

Import `crypto` from 'node:crypto' (or use globalThis.crypto.randomUUID() which is available in Node 22).

**2. Extend `src/middleware.ts`:**

The current middleware uses `authkitMiddleware` which returns a middleware function. We need to wrap it to add user sync logic AFTER auth succeeds.

Per `@workos-inc/authkit-nextjs` docs, `authkitMiddleware` supports a `debug` option but does NOT have an `onSuccess` callback. Instead, create a custom middleware that:
1. Calls `authkitMiddleware(options)` to get the middleware function
2. Returns a new middleware function that:
   a. Calls the authkit middleware to get the response
   b. After auth succeeds, checks if the request is for a protected route (starts with '/app')
   c. If protected, uses `getSession()` from `@workos-inc/authkit-nextjs` to get the current user
   d. Queries `db.selectFrom('users').where('id', '=', user.id).select(['last_synced_at']).executeTakeFirst()`
   e. If user not found OR `last_synced_at` is older than 5 minutes, upsert the user record (same pattern as callback)
   f. Per user decision: self-healing — if user exists but personal team is missing, recreate it
   g. Per user decision: auto-sync — when WorkOS profile changes (detected by name/avatar diff), update user record AND personal team name
   h. Validates `active_team_id` cookie if present: check that user has a membership in that team. If not, clear the cookie.
   i. If no `active_team_id` cookie and user has exactly one team, auto-set the cookie to that team (per user decision: single team = auto-select)

**Important middleware constraints:**
- Keep the staleness check fast: one SELECT query, compare timestamps
- Only write to DB when stale (> 5 min since last_synced_at) — per user decision
- The middleware runs on every request, so minimize DB calls for non-stale users
- Use `try/catch` around all DB operations so a DB error doesn't block the request
