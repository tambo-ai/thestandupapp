  <action>
Create `src/lib/schema.ts` with TypeScript interfaces for all tables:

**UsersTable** (global):
- `id: string` — WorkOS user ID (e.g., "user_01JYEX..."), PRIMARY KEY
- `email: string` — unique
- `name: string | null`
- `avatar_url: string | null`
- `last_synced_at: string` — ISO 8601 timestamp for staleness check
- `created_at: Generated<string>` — defaults to datetime('now')
- `updated_at: Generated<string>` — defaults to datetime('now')

**TeamsTable** (global):
- `id: string` — crypto.randomUUID(), PRIMARY KEY
- `name: string`
- `slug: string` — unique, URL-friendly identifier
- `is_personal: number` — SQLite boolean (0 or 1). Per user decision: teams table includes is_personal flag.
- `created_at: Generated<string>`
- `updated_at: Generated<string>`

**MembershipsTable** (team-scoped):
- `id: string` — crypto.randomUUID()
- `team_id: string` — FK to teams
- `user_id: string` — FK to users
- `role: 'owner' | 'member'` — per user decision: two roles only
- `created_at: Generated<string>`
- UNIQUE constraint on (user_id, team_id)

**ConnectionsTable** (team-scoped — stub for Phase 3):
- `id: string`
- `team_id: string` — FK to teams
- `user_id: string` — FK to users
- `provider: 'github' | 'linear'`
- `workos_connection_id: string`
- `status: 'active' | 'inactive' | 'error'`
- `created_at: Generated<string>`
- `updated_at: Generated<string>`

**InviteLinksTable** (team-scoped):
- `id: string`
- `team_id: string` — FK to teams
- `created_by: string` — FK to users
- `token: string` — unique, crypto.randomUUID() for URL
- `max_uses: number | null` — null = unlimited. Per user decision: configurable max_uses.
- `use_count: number` — default 0. Per user decision: count-only tracking.
- `expires_at: string | null` — null = never expires. Per user decision: default 7-day, configurable.
- `revoked_at: string | null` — null = not revoked
- `created_at: Generated<string>`

Export two database interfaces:
- `GlobalDatabase` — `{ users: UsersTable; teams: TeamsTable }`
- `TeamScopedDatabase` — `{ memberships: MembershipsTable; connections: ConnectionsTable; invite_links: InviteLinksTable }`

Also export a `FullDatabase` type that is `GlobalDatabase & TeamScopedDatabase` — needed for bootstrap transactions that span global and team-scoped tables (e.g., creating a team + first membership).

Create `src/lib/db.ts` with:

1. A shared `LibsqlDialect` instance using `process.env.TURSO_DATABASE_URL` and `process.env.TURSO_AUTH_TOKEN`.

2. `export const db = new Kysely<GlobalDatabase>({ dialect })` — global accessor for users and teams tables only.

3. `export function teamDb(teamId: string)` — returns an object with four methods:
   - `selectFrom(table)` — calls `kysely.selectFrom(table).where('team_id', '=', teamId)`
   - `insertInto(table)` — returns `kysely.insertInto(table)` (caller must include team_id in values — enforced by TypeScript types since team_id is required in MembershipsTable etc.)
   - `updateTable(table)` — calls `kysely.updateTable(table).where('team_id', '=', teamId)`
   - `deleteFrom(table)` — calls `kysely.deleteFrom(table).where('team_id', '=', teamId)`

   The `teamDb` function must create a new `Kysely<TeamScopedDatabase>` instance using the same dialect. Do NOT cache or reuse the instance (per research pitfall #2).

4. `export function getFullDb()` — returns `new Kysely<FullDatabase>({ dialect })` for bootstrap/transaction operations that need to span both global and team-scoped tables. Add a JSDoc comment: "Only use for bootstrap transactions (e.g., creating team + membership). Regular queries should use db or teamDb()."

Import `Generated` from 'kysely' in schema.ts.
