1. **Create `apiFetchForMembers` helper** — A new helper function in tambo.ts that handles the team-wide aggregation pattern:
   ```typescript
   async function apiFetchForMembers<T>(
     url: string,
     memberIds: string[],
   ): Promise<{ results: Array<{ memberId: string; memberName: string; data: T }>; errors: Array<{ memberId: string; memberName: string; error: string }> }>
   ```
   - Takes a base URL and array of member IDs
   - Calls `fetch` for each member in parallel using `Promise.allSettled`, appending `forUserId=<memberId>` to the URL
   - For fulfilled results: extracts data, tags with memberId/memberName
   - For rejected results (401 = not connected, 403 = unauthorized, other): captures error message
   - Returns `{ results, errors }` — never throws
   - Member name lookup: The AI already has team_roster via contextHelpers. The tool receives memberIds from the AI (which extracted names from context). Include memberName in the output as a placeholder — the tool can accept `memberNames` alongside `memberIds` or the AI can look up names from context.

   Simpler approach: Have each tool accept `memberIds` as `Array<{ id: string; name: string }>` so names are always available in the aggregated output.

2. **Modify `searchIssues` tool** — Add scope/memberIds parameters:
   - Add to inputSchema: `scope: z.enum(["personal", "team"]).optional()` and `memberIds: z.array(z.object({ id: z.string(), name: z.string() })).optional()`
   - Update description: "Search Linear issues. Use scope='team' to search across all team members (the AI knows the roster from context). Pass memberIds to query specific members. Results include attribution."
   - In tool function: if `scope === "team"` or `memberIds` is provided, use `apiFetchForMembers` to iterate members. If `scope === "team"` without `memberIds`, the AI should pass all connected members from team_roster (instruct this in description).
   - For team scope: return results with `memberName` field on each item. Flatten all members' results into a single array with attribution.
   - For personal scope: existing behavior unchanged (no forUserId)
   - Update outputSchema to include optional `memberName` field on each item

3. **Modify `listTeams` tool** — Add scope parameter. For team scope, iterate members. Note: this is a Linear-specific "team" (not app team). The scope parameter controls whose Linear account is queried.
