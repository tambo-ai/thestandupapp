  <files>src/lib/github-client.ts, src/lib/linear-client.ts, src/lib/team-context.ts</files>
  <action>
1. **src/lib/github-client.ts** — Add `withGitHubTokenForUser` alongside the existing `withGitHubToken`. This new wrapper:
   - Calls `withAuth({ ensureSignedIn: true })` to get the requesting user's identity
   - Reads `forUserId` from `request.nextUrl.searchParams`
   - If `forUserId` is present and differs from current user: validates both users share a team via a `memberships` self-join on `getFullDb()` (see RESEARCH.md Pattern 1 for exact query). Returns 403 if no shared team.
   - Calls `getWorkOS().pipes.getAccessToken({ provider: "github", userId: targetUserId, organizationId })`. For `organizationId`: when `forUserId` is set, query the team's `workos_organization_id` from the shared team row; otherwise use the session's `organizationId`.
   - On token failure: returns JSON `{ error: "GitHub not connected", code: result.error, forUserId: targetUserId }` with 401
   - On success: passes token + request to the inner handler
   - Keep the existing `withGitHubToken` completely unchanged (write operations use this)

2. **src/lib/linear-client.ts** — Add `withLinearClientForUser` following the identical pattern as above but for `provider: "linear"` and returning a `LinearClient` instance.

3. **src/lib/team-context.ts** — Create new file exporting:
   - `TeamMember` interface: `{ id: string; name: string | null; email: string; avatarUrl: string | null; role: "owner" | "member"; connections: { github: "connected" | "not_connected"; linear: "connected" | "not_connected" } }`
   - `getTeamMembersWithConnections(teamId: string, orgId: string | null)`: Queries `memberships` + `users` join for the given team, then calls `Promise.allSettled` to check each member's GitHub and Linear connection status via `getWorkOS().pipes.getAccessToken()`. Uses `orgId` (team's `workos_organization_id`) for all Pipes calls. Returns `TeamMember[]`. Each individual member's token lookup is wrapped in try/catch so one failure doesn't block others.

IMPORTANT: In the `withGitHubTokenForUser` shared-team validation query, also `select` the team's `workos_organization_id` by joining with the `teams` table so you can pass it to `getAccessToken`. This avoids a second DB query.
  </action>
