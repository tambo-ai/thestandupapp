<task type="auto">
  <name>Task 2: Server actions and middleware updates</name>
  <files>src/lib/team-actions.ts, src/middleware.ts</files>
  <action>
1. Extend `src/lib/team-actions.ts` with three new server actions (keep existing setActiveTeam and getActiveTeamId):

   **createTeam(name: string, slug: string):**
   - `withAuth({ ensureSignedIn: true })` to get current user
   - Validate slug format: lowercase alphanumeric + hyphens, 3-50 chars. Normalize: `name.toLowerCase().replace(/[^a-z0-9]+/g, '-').replace(/^-|-$/g, '')`
   - Check slug uniqueness in DB (SELECT from teams WHERE slug = slug)
   - If not unique, throw error with user-friendly message
   - Soft limit check: count user's non-personal teams. If >= 5, still proceed but log a warning (don't block per user decision)
   - Call `getWorkOS().organizations.createOrganization({ name })` to provision WorkOS Organization
   - In a transaction via getFullDb():
     - INSERT into teams: { id: randomUUID, name, slug, is_personal: 0, workos_organization_id: org.id }
     - INSERT into memberships: { id: randomUUID, team_id, user_id: user.id, role: 'owner' }
   - Call `workos.userManagement.createOrganizationMembership({ organizationId: org.id, userId: user.id, roleSlug: 'admin' })`
   - Create default invite link: INSERT into invite_links { id: randomUUID, team_id, created_by: user.id, token: randomUUID }
   - Call `switchToOrganization(org.id)` to set WorkOS session org context -- NOTE: this may throw a redirect, do NOT wrap in try/catch that swallows it
   - Set active_team_id cookie to the new team's ID
   - Return { teamId, slug }

   **switchTeam(teamId: string, workosOrgId: string | null):**
   - `withAuth({ ensureSignedIn: true })` to get current user
   - Verify membership (reuse existing setActiveTeam's membership check pattern)
   - If workosOrgId is not null, call `switchToOrganization(workosOrgId)` -- for real teams
   - If workosOrgId is null (personal workspace), skip switchToOrganization
   - Set active_team_id cookie
   - NOTE: switchToOrganization may throw a redirect; let it propagate naturally

   **joinTeam(teamId: string, inviteToken: string):**
   - `withAuth({ ensureSignedIn: true })` to get current user
   - Validate invite token: SELECT from invite_links WHERE token = inviteToken AND team_id = teamId AND revoked_at IS NULL
   - Check expiry (expires_at) and max_uses vs use_count
   - Check if user is already a member (SELECT from memberships WHERE user_id AND team_id). If yes, return { alreadyMember: true }
   - Look up team to get workos_organization_id
   - In a transaction:
     - INSERT membership { id: randomUUID, team_id, user_id: user.id, role: 'member' }
     - UPDATE invite_links SET use_count = use_count + 1 WHERE id = invite.id
   - Create WorkOS org membership: `workos.userManagement.createOrganizationMembership({ organizationId: team.workos_organization_id, userId: user.id })`
   - Return { teamId, teamName: team.name }

2. Update `src/middleware.ts`:
   - Add `/invite/:path*` to the `unauthenticatedPaths` array so unauthenticated users can see invite landing pages
   - The existing matcher already includes broad patterns, but verify `/invite` paths are NOT redirected to sign-in. Since the matcher has `/app/:path*` and `/api/:path*`, the `/invite/[token]` route at the root level may not be matched. If it's not matched, middleware won't run at all -- which is fine for a public route. But add it to `unauthenticatedPaths` as a safety measure anyway.
   - Also add logic: when a user visits `/invite/*` with a valid session, set a `pending_invite_token` cookie from the URL path so the join flow can use it after auth. Actually, the invite page handles this client-side with a server action, so no middleware cookie is needed. Just ensure the route is accessible.
