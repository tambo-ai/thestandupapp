**Part C: Member row rendering.**

For each member row, keep existing avatar + name/email + role badge layout. Add a three-dot menu button (MoreVertical icon from lucide-react) at the end of each row IF:
- isOwner is true AND
- the member is NOT the current user (userId) AND
- the member is NOT an owner

The three-dot menu is a simple dropdown (absolute positioned div) with one option: "Remove". Use a `menuOpenId` state to track which menu is open. Clicking outside or pressing Escape closes it.

When "Remove" is clicked:
1. Close the menu
2. Set `confirmingId` to the member's id
3. The row transforms to show inline confirmation: "Remove {name} ({email}) from {teamName}?" with "Remove" (red) and "Cancel" buttons
4. On confirm: call DELETE /api/teams/members with `{ teamId, userId: member.id }`
5. On success: set `removingId` to member.id, wait 300ms (fade/slide-left animation), then clear removingId and call refetchAll
6. On cancel: clear confirmingId

Each member row gets a transition class: `transition-all duration-300 ${removingId === member.id ? "opacity-0 -translate-x-4 h-0 overflow-hidden" : ""}`

For the current user's own row: no three-dot menu (leave is via dedicated button).

**Part D: Pending invitation row rendering.**

After all member rows, render invitation rows. Each pending row:
- Generic silhouette avatar (User icon from lucide-react in a gray circle)
- For email type: show email address. For link type: show "Invite link ({useCount} uses)"
- Below the label: "Invited by {invitedBy}, {relative time}" -- use a simple relative time helper (e.g., "2 days ago", "just now") computed from createdAt
- "Pending" badge (amber/yellow tint) instead of role badge
- If isOwner: three-dot menu with type-specific options:
  - Email: "Resend" and "Revoke"
  - Link: "Copy link" and "Revoke"

Resend action: POST /api/teams/invitations `{ teamId, action: "resend", invitationId: inv.id, type: "email" }`. On success, set resentId to inv.id, show "Resent" text inline, fade after 2s.

Revoke action: POST /api/teams/invitations `{ teamId, action: "revoke", invitationId: inv.id, type: inv.type }`. Animate out (same pattern as member removal), then refetchAll.

Copy link action: `navigator.clipboard.writeText(inv.url)`, show brief "Copied!" text.

**Part E: Leave team button at bottom of Members tab.**

After the member/invitation list, add a divider and "Leave team" button (red-tinted text, not a full red button -- subtle but clear).

When clicked: set confirmingLeave to true. Show inline confirmation: "Leave {teamName}? You'll lose access to this workspace." with "Leave" (red) and "Cancel" buttons.

On confirm: POST /api/teams/leave `{ teamId }`. On success, redirect using `window.location.href = '/app'` (middleware will handle switching to personal workspace since active_team_id cookie is now invalid). On error (last owner), show the error message inline: "You're the only owner. Transfer ownership before leaving."

On cancel: clear confirmingLeave.

Simplest: add a small count badge directly in the tab rendering by having MembersTab manage its own tab label via a callback, OR just show it as static text since the tab is rendered in the parent.

Actually, simplest approach: in the TeamSettingsModal parent, when rendering the tabs array for non-personal teams, just use "Members" as the label. The count can be shown inside the tab content header instead (e.g., "3 members, 2 pending" at the top of the list). This avoids prop-drilling complexity. Per Claude's discretion on this item, this is a reasonable choice.
